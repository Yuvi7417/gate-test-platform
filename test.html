What is Relational Schema?

Relational Schema represents the logical structure of a database in terms of relations (tables), attributes (columns), and constraints.

Why Relational Schema is Used?

  • Defines database structure clearly
  • Helps in data organization
  • Ensures consistency and integrity

Components of Relational Schema

  • Relation (Table)
  • Attributes (Columns)
  • Tuples (Rows)

Types of Keys

  • Super Key
  • Candidate Key
  • Primary Key
  • Foreign Key

Super Key

  • Set of attributes that uniquely identify a tuple
  • May contain extra attributes

Candidate Key

  • Minimal super key
  • No redundant attributes

Primary Key

  • Chosen candidate key
  • Cannot have NULL values

Foreign Key

  • Attribute that refers to another table
  • Maintains referential integrity

Functional Dependency

  • Represents relationship between attributes
  • Denoted as X → Y

Important Concepts in Relational Schema

  • Keys and constraints
  • Functional dependencies
  • Schema design

Applications of Relational Schema

  • Database design
  • Query processing
  • Data modeling

Common GATE Question Types

  • Identify keys (candidate, primary)
  • Functional dependency problems
  • Determine minimal keys
  • Schema-based reasoning questions

Common Mistakes in Relational Schema

  • Confusing super key and candidate key
  • Ignoring minimality condition
  • Incorrect functional dependency interpretation

🔥 Key Example

If a relation has attributes (A, B, C):

  • If A → B and A → C, then A is a candidate key

🔥 Key Comparison

Key Type Definition
Super Key Uniquely identifies a tuple
Candidate Key Minimal super key
Primary Key Selected candidate key
Foreign Key References another table

🔥 Key Concept

  • Every candidate key is a super key
  • Primary key is chosen from candidate keys
  • Functional dependency defines attribute relationships
